# M05 accelerator foundations

This is an offline, unreleased foundation for [#189](https://github.com/Jamula/Jamula-www-Website/issues/189), not a deployable service. Default and fallback policies deny. Named app-role policies require an explicitly supplied `CustomerContext`, the same sole authenticated identity used to resolve it, and an exact role present in both that identity and a current server membership snapshot. No role implies another role.

Run the offline policy tests with the .NET 11 SDK:

```powershell
dotnet run --project accelerator\Authorization.Tests\JamulaAccelerator.Authorization.Tests.csproj --configuration Release
dotnet run --project accelerator\Telemetry.Tests\JamulaAccelerator.Telemetry.Tests.csproj --configuration Release
```

The telemetry helper emits only a fixed completion-event span name, fixed outcome labels, caller-supplied duration, and counts. Spans represent recording, not operation duration; the duration metric represents the caller's measurement. Root spans intentionally do not inherit request baggage or trace state and therefore do not preserve distributed parentage. It does not configure an OpenTelemetry exporter or sanitize telemetry emitted by the host, dependencies, request handlers, or other instrumentation. Listener failures propagate to the caller; the helper does not execute or wrap business operations. If a metric listener and then an activity-stop listener both throw, the activity-stop exception takes precedence. Do not call the helper from an operation's `finally` block: integration must isolate and report instrumentation failures without masking results or exceptions before production use. End-to-end content suppression remains an integration and review gate.

`CustomerContextResolver` expects the result of a trusted, configured authentication scheme and a server-owned membership store. The host must obtain that result from `HttpContext.AuthenticateAsync` for the configured scheme, not construct it from request data; comparing the ticket's scheme name is not token validation. The host must configure Microsoft.Identity.Web to validate the single Entra tenant, issuer, audience, signature, and token lifetime and expose exactly one raw `tid` and `oid` claim; untrusted claim transformations must not modify that identity. The ticket must include validated token expiry in `AuthenticationProperties.ExpiresUtc`; when supplied, `IssuedUtc` is treated as the token's not-before bound. No such authentication or store is provided here. Resolution uses configured tenant IDs, never a request-selected tenant, and rejects missing, ambiguous, inactive, mismatched, or expired membership snapshots. The context's identifiers, roles, and validity bounds are frozen; each policy decision rechecks the bound identity and clock. The context expires at the earlier of the token and membership expirations. It is not proof of continuous membership: bind it to one request and revalidate live authorization for each protected resource and retrieval. Keep denial reasons internal and sanitize store errors.

The named policies are resource-based: the caller must explicitly pass the resolved context to `IAuthorizationService`. A normal endpoint policy whose resource is an `HttpContext` does not automatically supply it and is denied. These policies do not authorize individual resources or validate a token themselves. This foundation also lacks the required authentication time and server-generated correlation ID; do not use it to authorize privileged or step-up operations. Do not expose customer endpoints or treat these foundations as a complete authorization boundary. Aspire, Microsoft.Identity.Web and membership-store integration, object authorization and revocation tests, end-to-end content-suppressed telemetry, client-owned Azure deployment, and offline integration tests remain outstanding in #189. The connector/RAG work in #188 and the independent review and exact-SHA human release gate in #194 also remain open.
